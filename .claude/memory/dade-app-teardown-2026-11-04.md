**What DADE is (crawled 2026-11-04, v1.4.7).** Solo-dev browser digitizer (GitHub `jmtrafny`), React/Vite front on Vercel, Python API at `api.dade-app.com` (its converter lists pystitch/pyembroidery's 40 read formats), founding sponsor Ember. PNG <= 1024 px, free tier 5 colours, **fixed 10 px/mm with no target width** (a 418-px logo is 36.7 mm, period; resize = resample the PNG). Ten generators are declared by the server (`GET /api/v1/generators/schemas`: each param with min/max/step/unit/advanced plus a `preview.archetype` the client draws procedurally, so the Fills tab shows a pattern before any generation). Every island defaults to Tatami and the user picks satin by hand; underlay OFF, trims OFF ("Trim jumps over 0 = off"), DST trim encoded as N consecutive jumps with N user-set 1-10 (ours hardcodes 3 in `src/dst.js`). Stitch Editor beta edits single stitches/runs into a separate copy. Its own words: no photos, gradients or fine lettering.

**MFab hat head-to-head at DADE's 36.7 mm (main 053ed41c, Studio `hat_front` config, all files through `stitchviz.render_design`).** DADE: 2,561 st, 1.7 m thread, 35 jumps all uncut (19 over 5 mm), 45% of black-block stitches 0.1-0.3 mm (tatami row-advance on 2-3 mm strokes), no underlay - yet its lit render READ as the art, because it sews one black mass and leaves the keylines bare. Ours default (stage 0 says `photo_scene`, pinned in `test_stage0_texture_gate.py`; rembg prep then lettering): 5,348 st, 7.7 m, 12 trims, white keyline satin sub-mm, small text smeared, preflight B. Ours with `forced_class=flat`: 4,364 st, blocks **White then Black**, black buries the keyline = solid blob, preflight C (card proposed 11-04). At 113.5 mm (the pro's hat size) both our routes order Black/White/Black and read correctly; DADE cannot reach that size from this PNG without a >1024 px upload.

**Hat-size rematch at DADE's 100.8 mm (11-04, 1,024-px upscale injected into DADE's file input from the page; DADE detected 276 islands).** DADE: 9,070 st, 10.9 m, 492 jumps of which 265 over 5 mm, 38% of stitches under 0.3 mm (greys sewn as edge confetti), black mass + bare keylines, reads as the art. Ours default route: 19,096 st, 48.7 m, 20 trims, big letters right but a white satin blob covers WE+L of WELDING, preflight C `LETTERING_ILLEGIBLE`. Ours flat-forced: 19,454 st, 52.9 m, WELDING mostly right, preflight B (31% letters match). So on this art DADE's picture reads at every size it can reach and ours has a size-dependent white-layer defect at 37 and 101 mm, clean at 113.5 mm; sent to the 37 mm session as a second case.

**Why it matters:** a weaker engine produced the more readable file at thumbnail size because it does less. **How to apply:** state the size before quoting any DADE-vs-ours picture; the four things worth taking are the user-set DST trim-jump count, the schema-driven param UI with procedural previews, mono digits on every readout, and converter/resize tool pages (our service already writes 8 formats). The crawl's raw files lived in a session scratchpad; the site, docs and bundles are public and re-crawlable in minutes.
