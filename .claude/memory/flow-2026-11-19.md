**"Flow" = the stitching preview is clean and consistent across every repeat of a like shape.** Kent, 2026-11-19, on the flag stripes sewn as rectangles (`satin_rectangles`, ON the same day: "Flip ON (Recommended)"): "That flag stripe has FLOW! ... notice how the white stripes are all the same, and the stitching preview is clean and consistent across every stripe except for 1 spot (minor issue). This is what I'm referring to when something does or doesn't flow. The ends of the flag previously did not have clean flow, now they do."

Before it the same message: "a square needs to be square / a circle round / a triangle needs 3 points / you need to do a better job reading the image before digitizing."

**Why:** the skeleton satin tier built each stripe from its own medial axis, so 13 identical rectangles sewed 13 slightly different ends (rounded 0.2-0.5 mm, right edge wandering 2.9 mm). Each stripe was "fine" alone; the set did not flow. The fix read the shape (a true rectangle, within 0.1 mm of its min rectangle) and sewed it by its geometry, so every stripe came out identical.

**How to apply:**
- Judge a render by whether like things sew alike: equal stripes equal, every end the same, every star the same, no one-off stitch. A stray stitch on one repeat breaks flow even when coverage is fine.
- Read the geometric primitive first (rectangle, circle, triangle/star point) and construct from it; a generic skeleton path that rounds corners or blunts points is the fault, not the art.
- Still open after this note: the flag's stars sew blunt-armed blobs (no points); the one "red dot" was the satin's first cross half-covered by its second stitch at the start end (shows only on the last-sewn colour).
