Kent ruled 2026-11-05 to ADD the floor row that [[free-digitizer-survey-2026-11-04]]
proposed ("keep heatstitch's untuned rule as a floor beside our classifier").

**Where.** `digitizer/tools/tripwire.py`, the tool a classifier PR already quotes
for per-job stitch-type kappa (the lettering board has no kappa). `tripwire floor
[--figures PASS.json] [--floor-dir DIR] [--floor-warn 0.05] [--write OUT]`, and
`tripwire check --floor` appends the same table to STDOUT only (not `--table`, not
the exit code). `check` without `--floor` is byte-for-byte what the nightly runs.

**What it reads.** heatstitch's 18 DSTs in `<primary checkout>/scratch_bench/heatstitch/`
(`default_floor_dir`: walk up from `.claude/worktrees/<lane>` to the repo root, so a
lane finds the main checkout's files). Each goes through `pro_baseline.kappas`, the
same reader as ours and the pro's. Table: ours / heatstitch (chance floor in
brackets) / margin / FLAG. No dir -> `n/a (no floor files)`; a job with no file is
`no file`, never 0. Flag only: exit 0 always.

**Why laptop-only.** The files are third-party stitch files in a PUBLIC repo: gitignored,
no render of them under docs/ ([[pro-renders-local-only-2026-10-27]]). The cloud
nightly ([[nightly-tripwire-2026-11-02]]) cannot see them, so it stays untouched.

**Snapshot.** `docs/scoreboards/heatstitch-floor-2026-11-05.md`: 18 rows on main
`67319af2`, generated by `floor --write`. Read the numbers there; the median ours/floor
is the instrument, a single job is not.

**Trap.** Ours here is the LAPTOP's Windows run, the committed ledger is cloud Linux:
three golden-level numerics differ, so quote margins from one machine only.
