**What Stitchist is (crawled 2026-11-04, "appliquégen" v1.1.0, build 08bbf5e7bace).** Browser digitizing studio with the engine SERVER-SIDE: plain-JS client (19.8k lines, `digitizer.js` 610 KB, no framework) over a FastAPI/uvicorn Python engine behind Caddy, pyembroidery writers. Every stitch is an API round trip: `/api/import` (SVG + DesignConfig -> cached session) -> `/api/sequence` (player) -> `/api/build` -> `/api/download/{session}` (zip: colour-chart PDF, 2096-px thread-textured preview, per-hoop DST/PES). Also `/api/autodigitize/analyze|build`, `/api/magicwand`, `/api/pushpull` (11 fabrics with a `give` factor: leather 0.55 ... woven 1.0 ... linen 1.2), `/api/satin-angles`, `/api/autoredwork`, `/api/convert` (47 formats read, 8 written), `/api/threads/match`. Free: whole editor, DST+PES, 32 satin + 26 fill fonts, magic wand 5 clicks, **Auto Digitize 1 run, account required (401 `auth_required`)**. Pro $50 once. Operated from the US, support@stitchist.app, Stripe, cookieless first-party events, CSP `connect-src 'self'`. A `mode: desktop` build exists in `plan.js` (plan = pro, no gates).

**Auto Digitize (what it decides).** 4 steps: Trace (target longest side, default 90% of hoop min capped 100 mm; tolerance 0-100 def 20; detail 0-100 def 50, auto-raised) -> Suggestions as yes/no questions with the answer pre-picked and a "Why?" carrying numbers (MFab: "stitch these inner areas? 134 mm2", "lines: keep as fill / satin / triple run", "keep background?") -> Stitches per object (satin/fill/running/off, machine stop) -> Colors (Brother chart, merge/turn off). Build sews fills first, line-work on top, fills traced under the lines. **The trace is re-run at the chosen size: MFab at 100 mm = 13 objects / 3 colours / ~5,536 st; at 36.7 mm = 4 objects / 2 colours** (the small white letters merged into one "White lines" fill).

**MFab hat head-to-head at DADE's 36.7 mm (same 418-px PNG; one renderer; sheet in `pro_renders/stitchist-teardown-2026-11-04/sheet_mfab_36.7.png`, DADE's and our files copied to `.../dade/`).** Stitchist 3,018 st, 18 trims, 1 colour change, 3.7 m, black then white: readable at thumbnail, keyline + "AND WELDING LLC" sewn as fill rows across ~0.5 mm strokes, so the white block is 82% stitches under 1 mm (36% under 0.3). DADE 2,561 st, 0 trims, 1.7 m, 75% of black under 1 mm, keylines bare. Ours default 5,348 st / 7.7 m (2% under 0.3 mm, small text smeared); ours flat 4,364 st = blob. Stitchist layers the white keyline OVER the black like the pro does; it just does it with tatami, not satin. Fabric stayed Cotton/woven (Cap front did not take in the pane).

**Why it matters:** a second competitor, with a real engine and a review-style wizard, produces a file in the same thumbnail-size failure class (sub-mm fill rows) that DADE does; the readable-at-size test from [[dade-app-teardown-2026-11-04]] still sorts them. **How to apply:** quote stitchist numbers only with the size; worth taking: suggestions-with-why (numbers in the rationale), per-object live stitch counts in the sequence panel, the export bundle (chart PDF + preview PNG + basting frame + max-stitch split + PES v1/v6), "errors don't spend the free run", the Learn panel that observes editor state instead of trapping the pointer, Canvas2D-only deterministic thread render baked in a worker. The fabric `give` table is THEIR constant, unverified by a sew-out (ROADMAP gate 1). Traps: the page cannot fetch cross-origin (base64-inject a file into `.dz-file-auto`); the built-in pane saved the zip as a UUID `.tmp` in Downloads.
