# Scope digest — licence and dependencies

Sources: `docs/inkstitch-research-2026-08-10.md`, `docs/sam-alternatives-research-2026-08-11.md`, `docs/pystitch-evaluation-2026-08-11.md`, `docs/font-license-audit-2026-07-31.md`, `docs/lawyer-brief-cc-by-sa-2026-08-04.md`, `docs/bluenesia-permission-archive-2026-08-04.md`.

## Hard licence constraints

- **Ink/Stitch is GPL-3.0-or-later.** No literal code, no near-verbatim translation, no "port the function and rename the variables." Every algorithm cited with a `lib/stitches/*.py` or `lib/elements/satin_column.py` path is GPL code; clean-room only, with the Ink/Stitch source not open in the same editor session as the implementation work. Concepts, geometry, published parameter names/taxonomies and file-format knowledge are not copyrightable and are fair game. — inkstitch-research §0, §10 "Legally off-limits"
- **`precious` font is GPL-3.0** — Ink/Stitch's one font under the code licence. Any future import from `inkstitch/embroidery-fonts` must explicitly exclude it. — inkstitch-research §4.2; font-license-audit §2 census note
- **`pystitch` is MIT** — confirmed against the LICENSE file text and `pyproject.toml` (`license = "MIT"`). Runtime dependency use carries no copyleft. This is the one place literal *use* of Ink/Stitch's own dependency is available. — inkstitch-research §0, §6; pystitch-evaluation §2
- **FastSAM is AGPL-3.0 — disqualified.** LICENSE file is AGPL (fetched twice); the README's "Apache 2.0" claim links to that same AGPL file, and a broken cross-reference is not a grant. `ultralytics` is AGPL too, Ultralytics claims AGPL covers weights, and FastSAM vendors the whole `ultralytics/` tree in-tree so you cannot route around it. Ultralytics' own licence page names "any commercial product", "proprietary/closed-source", and "internal business tools" as requiring a paid Enterprise licence. Using it means open-sourcing EMB-Bot or buying that licence. — sam-alternatives §2.1
- **EdgeSAM is NTU S-Lab License 1.0, non-commercial — disqualified.** "Redistribution and use for non-commercial purpose… are permitted." GitHub reports NOASSERTION. Same category as the `bria-rmbg` rejection. — sam-alternatives §2.2
- **MobileSAM's repo mixes licences.** Root is genuine Apache-2.0 (byte-identical canonical text), but `MobileSAMv2/` vendors Ultralytics YOLO with `AGPL-3.0 license` headers on every file. A `git clone` pulls AGPL into the tree. If ever adopted: vendor `mobile_sam/` only, as a written rule in the vendoring script. — sam-alternatives §2.3
- **SAM 3 / 3.1 ship a custom non-OSI "SAM License."** Permits commercial use, but must be passed through on redistribution, §8 lets Meta amend it unilaterally with immediate effect, and §1.b.iv prohibits use that would "reverse engineer, decompile or discover the underlying components." HuggingFace repo is `gated: "manual"`. — sam-alternatives §2.5
- **OFL-1.1 (52 shipped fonts) requires the full licence text plus copyright notice with every copy** — a link is not sufficient; stand-alone text files or machine-readable metadata satisfy it. EMB-Bot was in breach of OFL condition 2 (48 of 69 fonts had no licence text on disk, and the build's copy step shipped none); remediated 2026-08-04 via sidecars, the copy step, credits and full text embedded in every `.embf`. — font-license-audit §3, §8
- **OFL Reserved Font Names:** keep the "with Reserved Font Name X" declarations in shipped notices and never surface an RFN as a primary font name in UI/manifest/binary metadata. Scanned clean. — font-license-audit §3, §10
- **Zero ShareAlike ships.** All 13 CC-BY-SA fonts were pulled 2026-08-04 and CC-BY-SA-4.0 removed from `ALLOWED_LICENSES` so no new one can enter. — font-license-audit §9
- **`dejavufont` is Bitstream Vera Fonts License v1.00 + Arev, not CC-BY-SA** (upstream text fetched and read in full). Both explicitly forbid selling the font software typefaces "by itself" — only as part of a larger package. Neither is in `ALLOWED_LICENSES`. Pulled. — font-license-audit §7
- **CC-BY-SA-2.5 Geneva fonts carry a mandatory 1967 Hershey acknowledgement** (shipped verbatim). Relevant only if they are ever restored. — font-license-audit §3, §8 item 9
- **Unlicensed / unclear ONNX weight sources are hard stops for shipping:** `onnx-community/sam2.1-hiera-tiny-ONNX` has no model card and no declared licence; `lucasgelfond/webgpu-sam2` has no licence file; `axinc-ai/ailia-models`' repo root is NOASSERTION (model dir is Apache-2.0) — reference implementation only, never a weights source. Self-export from Meta's Apache-2.0 checkpoints with MIT `samexporter` is the clean provenance story. — sam-alternatives §5.3
- SAM 2.1, EdgeTAM, EfficientSAM, EfficientViT-SAM, SlimSAM, SAM 1, NanoSAM are all Apache-2.0 on code, and (except NanoSAM) on weights, verified against the licence files. — sam-alternatives §2

## Unresolved legal questions

- **Is a compiled `.embf` "Adapted Material" under CC-BY-SA 4.0 §1(a) / a "Derivative Work" under 2.5?** Gated on: a one-hour lawyer consult that only Kent can book (brief written and ready to send). **Does NOT block launch** — resolved by removal; it now only blocks the optional restore of the 13 pulled ShareAlike fonts, and decides whether restored binaries need BY-SA labelling. Attribution/notice duties are shipped either way. — font-license-audit §5, §9; lawyer-brief "Scope", "What rides on the answer"
- **Does BY-SA propagate onto customer deliverables** (generated DST/PES files, physical sew-outs)? Same consult; optional-feature only, same reason. — lawyer-brief sub-issue 3
- **`milli_marif_bold`** — permission is two French emails ("Vous avez ma bénédiction") plus the full OFL text; no English confirmation that the grant covers commercial embroidery distribution. Pulled. Gated on that email. Blocks only restore. — font-license-audit §4, §7
- **`tt_directors` / `tt_masters`** — OFL claim traceable only to a 1001fonts aggregator listing while TypeType sells these families commercially; residual takedown exposure. Pulled. Gated on foundry-grade verification. Blocks only restore. — font-license-audit §2, §7
- **`dejavufont` restore path** needs two decisions: whether Bitstream-Vera-derived fonts join the allowed policy set, **and** whether EMB-Bot's bare-`.embf`-download product model is compatible with the "no standalone sale" clause. The second is a product-policy question, not a label fix. Blocks only restore *today*, but the bare-download mechanism itself is a launch-surface question if any restricted-terms font ever ships. — font-license-audit §7, §8 item 8
- **`bluenesia_satin`'s permission grant exists only as two screenshots** in the April-2025 comment thread of PR #1686 (which is titled for different fonts). Existence, date, participants and context are archived; the designer's verbatim reply is not. Blocks only restore (the font is CC-BY-SA and already pulled). — bluenesia-permission-archive
- **`EMB-Bot-standalone.html` is a retired frozen artifact that still inlines all 21 legacy fonts including all 7 pulled ones.** Options: delete, regenerate once, or accept as non-distributed. Until then it must not be distributed. This is the one open font item that would be a **launch problem if that file is ever shipped**. — font-license-audit §10
- **SA-1B dataset licence text could not be retrieved** (Meta returns 403); the dataset page says "research purposes only." Applies equally to every SAM-distilled variant. A residual question for counsel, not a bar — Meta itself ships SAM/SAM2 weights trained on the same data under Apache-2.0. Blocks only the optional model-swap lane. — sam-alternatives §2.4, §8
- **SAM License §1.b.iv** needs legal review before anyone quantizes, prunes or distils SAM 3 weights. Optional-feature only. — sam-alternatives §2.5

## Claims marked unverified

- **The entire Ink/Stitch teardown is a summarizing-fetch survey, not a byte-for-byte read.** Its own header: "[V] below means 'verified via direct source/doc fetch this session,' not 'read in full.'" That includes the **GPL-3.0-or-later finding itself, which rests on "the repo's license footer"** — not on the LICENSE file text. The posture is almost certainly right, but the headline licence fact of the commercial gate has not been confirmed against the licence text in-repo. — inkstitch-research "Method", §0
- **Ink/Stitch's per-font licence census (51 OFL / 12 CC-BY-SA-4.0 / 2 CC-BY-SA-2.5 / 1 CC-BY-4.0 / 2 CC0 / 1 SEE-LICENSE-FILE) was not re-derived** by the teardown; only top-level claims ("no single repo-wide license") were checked live. The census is EMB-Bot's own earlier audit output. — inkstitch-research §4.2
- **Most font rows' evidence is the word "manifest"** — i.e. the licence label came from EMB-Bot's own auto-detected string, not from the licence text. `dejavufont` proves that channel can be flatly wrong (labelled CC-BY-SA; actually Bitstream Vera + Arev), and the cause is systematic: `licenseId()` matches the CC-BY-SA regex against the *adapter's own header claim* before reaching the real licence block, and would re-mislabel on every rebuild. Mitigated after the fact by a 68/68 sidecar-vs-`licenseId` crosscheck against upstream text — but any font whose row cites only "manifest" and predates that crosscheck should be treated as label-asserted. — font-license-audit §2, §7, §8 item 5
- **`excalibur_KOR` / `excalibur_small` are labelled CC0 from "public domain" wording, not a literal CC0 grant.** The doc flags this itself. — font-license-audit §2
- **`EfficientSAM`'s weights licence is an inference:** the README has no licence section at all; the claim rests on weights being committed in-tree under the root Apache-2.0 file. — sam-alternatives §3.4
- **`NanoSAM` weights have "no separate terms found"** yet the triage table marks it commercial-safe. Absence of terms is not a grant. — sam-alternatives §2 table, §3.7
- **`pystitch`'s MIT LICENSE has no named copyright holder** ("Copyright (c) 2018", blank) and PyPI's `info.license` is null. The doc explains both away as SPDX-declaration artifacts; that explanation is reasoning, not verification. — pystitch-evaluation §2
- **`pyembroidery` 1.5.1's own DST convention was not re-verified from its source** in the pystitch pass; the comparison leans on `export.py`'s docstring plus a real third-party DST file. — pystitch-evaluation §4.1, §4.2
- Method caveat: "no official SAM2 ONNX export" rests on the repo file tree plus README/INSTALL, not an exhaustive repo-wide grep (GitHub code-search returns 401 unauthenticated). — sam-alternatives §8

## Techniques adoptable at concept level

The line, stated once: geometry, conventions, parameter names and documented limitations are usable; the `lib/` implementations are GPL and are not. Every item below is concept-only.

- **Tatami:** Eulerian-path lineage (cites S0925772100000158); underpath travel graph built from three auxiliary gratings at +45°/−45°/+90° to the fill angle with boundary edges weighted up; `gap_fill_rows` repeats a row where a discontinuity would distort fabric. **Row-spacing convention settled from the row-advance loop: row *i* sits at exactly `i * row_spacing`, no factor of 2** — same convention EMB-Bot already uses. Settles the definition question, not the magnitude question (0.40 vs 0.19 mm stays sew-out-gated). — inkstitch-research §1.1
- **Contour fill:** nested isocontours via `offset_curve`, a DiGraph containment tree with holes as a distinct node type, three strategies (inner-to-outer / single spiral / double spiral), entry buffer thresholds at 1.5× and 2.05× the offset spacing. Documented limitation confirmed: contour underlay uses the *fill angle*, not the contour — a verified differentiator. — inkstitch-research §1.3
- **Circular fill:** concentric circles from a centre, ring count from Hausdorff distance, joined by a **Fermat (double) spiral** specifically so the path doesn't get stuck in the middle. — inkstitch-research §1.4
- **Meander/stipple:** tile pattern → graph fitted to the shape, then grow a path by **iteratively replacing edges with longer detour paths through unvisited nodes** (depth ≤7), which makes self-avoidance structural rather than checked. Clean-room portable; needs its own tiling-to-graph construction. — inkstitch-research §1.5
- **Guided fill:** Copy / Offset / Buffer as a *named user-facing strategy switch* is the transferable idea; the Offset/Buffer maths is the normal-offset family EMB-Bot's own research already rejected for cusp/swallowtail failure. — inkstitch-research §1.6
- **Linear gradient:** blending is achieved purely by row banding, no per-pixel interpolation — same physical-row-alternation model EMB-Bot planned, with no error bound. — inkstitch-research §1.7
- **Tartan:** two-axis warp/weft crossing from a stripe palette, colour resolved by intersecting lines against per-stripe colour-band polygons, plus a herringbone variant. — inkstitch-research §1.8
- **Cross-stitch:** anchor-based Eulerian splicing of adjacent crosses with no connector stitch. Named fragility to avoid: anchors matched by exact float-tuple equality (integer lattice keys are strictly more robust). — inkstitch-research §1.9
- **Ripple stitch:** four guide modes (linear/circular/guide-line/satin-column), non-linear step distribution via an exponent, and an inverted invariant — self-crossing is *permitted by design*. Needs a guard-relaxation pass, not a drop-in. — inkstitch-research §1.10
- **Satin:** e-stitch and s-stitch are alternate *point-selection* strategies over the same two rails, cheap once rail extraction exists. Public underlay defaults: centre-walk 2 repeats at 3 mm; contour 3 mm length, 0.4 mm inset per side; zigzag 3 mm spacing. `short_stitch_distance` 0.25 mm triggering a sawtooth inset list `[0.15]` to avoid a uniform-inset ridge. Asymmetric two-value pull compensation per rail. — inkstitch-research §2
- **Strokes:** Zhao–Saalfeld curve simplification with angle-interval checking as a citable basis for running-stitch tolerance; bean stitch as a **per-position repeat pattern** (`[0,1,3]`), not a flat pass count. — inkstitch-research §3
- **Negative results — do not adopt:** `auto_run`'s flat 0.75 mm trim threshold and `auto_satin`'s `should_trim()` source-overlap check are both *less* sophisticated than EMB-Bot's coverage-routed chaining laws. And Ink/Stitch has **no shape-classification heuristic at all** (`auto_satin` assumes the human already typed each element), so there is nothing to benchmark `is_satin_candidate` against. — inkstitch-research §2, §3, §5
- **Params/UI patterns (no copyright surface at all):** only user-touched fields get written back on a multi-select edit; parent/dependent paired tabs that auto-disable mutually-exclusive stitch types; a reserved `__LAST__` preset name for "use last settings." — inkstitch-research §7
- **Validation surfaces:** on-canvas spatial pointers at the exact problem location (Ink/Stitch has no aggregate score; EMB-Bot's preflight is ahead on aggregation and behind on locality), plus a point-local density heatmap via an STRtree neighbour count (red ≥6 within 0.5 mm, yellow ≥3). — inkstitch-research §9.2
- **Worksheet:** estimated thread consumption and per-colour realistic preview thumbnails. Knockdown/laydown fill for high-pile fabric (second vendor confirming a gap EMB-Bot already identified). `.gpl` palettes are trivial plain text, so Ink/Stitch's ~40-44 brands are cheaply diffable against EMB-Bot's 68. — inkstitch-research §9.3, §9.6, §8
- **SAM lane:** the one technique worth stealing is EfficientSAM's notebook design — push the **whole prompt grid through one batched forward pass** instead of looping per prompt (and `samexporter`'s dynamic `num_labels` axis makes this exportable). `axinc-ai`'s torch-free numpy AMG is a reference for the ~6 torch-bound helpers (`mask_to_rle`, stability score, `batched_mask_to_box`, uncrop, crop-edge test, NMS). — sam-alternatives §3.4, §5.3, §7

## Dependency risks

- **`pyembroidery` upstream is "possibly dormant"**; `pystitch` is maintained by the original author under the `inkstitch` org — but it has a single `main` branch, **no git tags**, and only two PyPI releases (1.0.0, 1.0.1). Zero third-party runtime deps, `requires-python >=3.9`. — pystitch-evaluation §2, §6
- **`pystitch`'s `read_dst` unconditionally runs `interpolate_trims`**, relabelling runs of ≥3 consecutive JUMPs as a synthesized TRIM. It touches no STITCH/COLOR_CHANGE entry, and this was **not verified against pyembroidery 1.5.1's own reader** — the single behavioural unknown in the swap. Close it with an explicit JUMP/TRIM-count assertion. — pystitch-evaluation §4.2
- `pystitch`'s README format counts don't reproduce from source (claims 46 read / 20 write; the generator gives 50 / 22). Substance holds; don't quote the number. — pystitch-evaluation §2
- **Footprint is torch, not weights.** Isolated venv site-packages 854 MB, of which torch plus its exclusive tail is ~635 MB (74%); the checkpoint is 156 MB of a ~1.03 GB problem. `cv2` is 117 MB present for exactly one lazily-imported function worth ~2% of runtime — and dropping it means reimplementing per-mask hole/island cleanup, which is *not* the same operation as the downstream whole-region floor. — sam-alternatives §4.3, §6.4
- **~4.8 s of fixed `import torch` + `import sam2` cost per image**, because the worker is a fresh subprocess. No config knob or model swap removes it; only leaving PyTorch, or a warm worker (own failure modes, out of scope). — sam-alternatives §1, §6.5
- **SAM2's optional `_C` CUDA extension was never built**, so `max_hole_area`/`max_sprinkle_area` post-processing **silently does nothing** and emits a UserWarning every call. Benign, but nobody should count on that cleanup. — sam-alternatives §6.5
- **Model downloads:** 156 MB checkpoint from `dl.fbaipublicfiles.com`; SAM 3's HuggingFace repo is gated on manual Meta approval per account — real friction for a build pipeline; SAM 3 checkpoints are 3.45/3.50 GB. — sam-alternatives §2.5, §3.0
- **No official SAM2 ONNX export exists** — `optimum-onnx` lists SAM and Hiera but not SAM2, and every ONNX path is community-maintained. `ibaiGorordo/ONNX-SAM2` predates the 2.1 release, self-describes as "use at your own risk", and has a broken conversion notebook. — sam-alternatives §5.2, §5.3
- **Dormant upstreams:** EfficientSAM last commit 2024-12-24 and that commit redirects to a successor project; SAM 1 last push 2024-09-18 (~23 months, README redirects to SAM 2); NanoSAM untouched since 2023-09-20 and is TensorRT/CUDA-only with no CPU path; EfficientViT-SAM last push 2025-09-05; SlimSAM 2025-09-27 and **vendors `torch_pruning/`, which needs its own licence check before shipping**. — sam-alternatives §3.3–3.7
- **ONNX quantization tooling risk:** ORT dynamic quantization silently became a no-op for transformer nodes after 1.20→1.21, closed `not_planned` — verify the artifact actually shrank. This Zen 2 CPU predates AMD VNNI, so int8 gains are optimistic. And one credible report has the **ONNX decoder running slower than PyTorch under exactly this AMG workload** — given the decoder is 92% of the cost, a port can make things worse. — sam-alternatives §5.4, §5.5
- **Font build pipeline is fragile in a clean checkout:** `scratch_ink/` is gitignored, 46 of 68 fonts had no local source JSON, and **running `build-embf.mjs --shipped-only` in such a checkout writes a 22-font manifest** — destructive. `licenseId()`'s detector will re-mislabel adapter-claim fonts on every rebuild until fixed. `satin-fonts.js` carries a COOKBOOK "do not delete" directive. — font-license-audit §7, §8, §10

## Sequence claims

- **Read the licensing section before any "should we port it" decision.** — inkstitch-research §0 (title line)
- **Read §1's measurement before §3's candidate list** — the encoder is only ~8% of cost, so the candidate comparison is misleading on its own. — sam-alternatives header, §1.2
- **SAM ranking order is stated as license safety → automatic mask generation works → footprint → speed.** — sam-alternatives §7
- **Tune `points_per_side` to 12 first; add `max_side_px=512` only if step 1's quality holds.** Do not combine an aggressive `max_side_px` cut with thin-detail artwork without inspecting the result. — sam-alternatives §6.2, §7 steps 1-2
- **Before committing to ONNX, verify three things in this order:** (1) measure Windows CPU latency yourself — none is published; (2) verify int8 actually shrinks *and* speeds up; (3) confirm mask parity against the torch path on existing fixtures. Do the config steps 1-2 first, then re-measure whether ONNX is still worth it. — sam-alternatives §7 step 5
- **EdgeTAM adoption is blocked on measuring image-mode quality vs SAM 2.1** (only video metrics published). **EfficientViT-SAM is only competitive inside an ONNX-first design** — revisit only if the ONNX project happens. **MobileSAM requires the `mobile_sam/`-only vendoring rule written down before adoption.** — sam-alternatives §7 recs 6-8, §2.3
- **`pystitch` swap is gated on running the test suite once, not on further research**, in four ordered steps: pin the dependency, mechanical import swap in 10 files, run the existing suite, add the JUMP/TRIM assertion. — pystitch-evaluation §5, §6
- **Build contour fill's inner-to-outer strategy first** — single/double spiral both require each parent to have only one child. Satin e/s-stitch is cheap **only once medial-axis rail extraction exists**; circular fill is cheap **only once contour-fill's ring machinery exists**. — inkstitch-research §1.3, §10 Tiers 2-3
- **Font audit ordering:** items 1-3 gate *which* fonts ship; items 4-9 gate *whether anything* ships; item 11 (lawyer) could run in parallel but "get the consult booked before first dollar" — since superseded by the §9 ShareAlike removal, which de-gates launch. — font-license-audit §6, §9
- **Do not distribute `EMB-Bot-standalone.html`** until it is deleted, regenerated from the pruned tree, or accepted as non-distributed. — font-license-audit §10
- **Implementation work must not happen with the Ink/Stitch source open in the same editor session.** — inkstitch-research §10
