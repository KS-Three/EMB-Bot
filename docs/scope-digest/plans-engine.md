# Scope digest — engine plans (what outlives execution)

Sources are all under `docs/superpowers/`. Paths below are relative to that.

## Design decisions that still govern

- **One shared `kept regions -> Quant` tail.** Every photo region former calls `stage2_photo_segment.kept_masks_to_quant()` (mean-Lab, area x class weights, `select_palette`, spool dedupe, separate enclosed population, warnings, debug viz). Rationale: several decisions in it are regression fixes with measured defects behind them (`main_thread_colors` vs `len(thread_indices)`, the enclosed population's own trailing label block, deliberately NOT trusting the merged label array's 0/nonzero background convention) — two copies would drift on exactly those. `plans/2026-08-10-sam2-segmentation.md § Task 1`
- **Warning field names stay algorithm-neutral.** `slic_segments` / `slic_*` mean "whatever the oversegmentation step produced", so SAM2 reuses them rather than forking the warning schema; only the unit noun (`raw_unit_label`) varies. `plans/2026-08-10-sam2-segmentation.md § Task 1`
- **Heavy ML deps live in their own venv behind a standalone worker + subprocess bridge** (`rembg_isolated/` pattern, reused for `sam2_isolated/`). The shared `.venv` exists to run a deterministic offline CPU-only pipeline against exact-pinned numpy/OpenCV that feed golden tests; torch would hand that resolution to its own transitive graph. Worker scripts import nothing from `digitizer_core` (AST-enforced) so they run in a venv with no package install. `plans/2026-08-10-sam2-segmentation.md § Task 2`
- **Never-raises seam contract:** `(result, reason)` tuple. Venv missing, checkpoint download failure, crash, timeout, unreadable output, or zero usable regions all degrade silently to the classical lane with an append-only warning code; the job always completes. Environment-level availability is a separate file-existence check (`*_unavailable_reason()`); per-call runtime failures are reported by the seam itself, because they are not knowable from disk. `plans/2026-08-10-sam2-segmentation.md § Tasks 3-4`
- **The explicit `subprocess.run(timeout=)` is the only starvation bound.** `digitizer_service/jobs.py`'s JobRegistry is a single-worker ThreadPoolExecutor with no per-job timeout and no cancellation — read the timeout as a queue-starvation bound, not a performance target. `plans/2026-08-10-sam2-segmentation.md § Global Constraints`
- **Deploy-time file locations are module-level constants, not `PipelineConfig` fields** (so tests monkeypatch them; a venv path is not a per-job parameter). `plans/2026-08-10-sam2-segmentation.md § Task 3`
- **Class routing is locked:** SAM2 only for `photo_subject`/`photo_scene`; `gradient` routes to `photo_segment` for an unrelated reason (k-means dithers ramps) and must never pick up SAM2 — a ramp has no distinct objects for an instance segmenter; `flat` never reaches the photo path. Flag defaults False. `plans/2026-08-10-sam2-segmentation.md § Task 5`
- **Weights/checkpoints are never committed** (past `model_data/README.md`'s "couple hundred KB" line); downloaded on first use to `~/.cache/sam2` via a `.part` file renamed on success, so an interrupted download can't poison the cache. Default tier `tiny`, CPU-only: disk and per-image latency outrank max accuracy. `plans/2026-08-10-sam2-segmentation.md § Task 2`
- **SAM2 overlap resolution paints in descending area order** so smaller nested masks win shared pixels — nested detail (eye in a face, badge on a jacket) is exactly what must survive as its own sewable shape. Ties break on `predicted_iou`, then generator order, for determinism. `plans/2026-08-10-sam2-segmentation.md § Task 2 `_paint_labels``
- **Pixels no mask covered (`-1`) are real artwork,** not garbage: SAM2 returns instances, not a partition, so they become one more label id, split into components, and judged by `resolve_small_regions` on their own merits. `plans/2026-08-10-sam2-segmentation.md § Task 4`
- **All "too small to sew" floors derive from `cfg.min_detail_mm`** — no new thresholds. SAM2's floor must be computed in the *downscaled* image's pixel space; an unscaled floor over-filters by 1/scale² (4x-15x at the 1024px cap) and deletes the detail the feature exists to keep. `plans/2026-08-10-sam2-segmentation.md § Task 4`
- **Label arrays are upsampled nearest-neighbour by numpy indexing,** never `cv2.resize` (rejects CV_32S; a float32 round-trip is silent-corruption risk) — interpolation would invent label ids. `plans/2026-08-10-sam2-segmentation.md § Task 4`
- **Palette selection is joint, chart-restricted weighted k-medoids over the whole region set** (replacing a per-region `chart.nearest_index` snap) so a fur ramp's regions share consolidated family shades; weights are area x class multiplier from face/subject priors. `plans/2026-08-10-sam2-segmentation.md § Task 1`
- **`max_colors` is a hard hint with bounded, floor-aware overflow.** `select_palette` may add up to `PALETTE_OVERFLOW_K = 3` medoids past the soft cap, but only while the worst-excess region's own floor is `<= excess_deltae * 0.5` — rescue a genuinely well-matchable region, never pad the palette for one no thread is near. The 0.5 threshold is derived from `PALETTE_EXCESS_DELTAE`, not a new magic number; designs that satisfy the bound within `max_colors` are untouched. `plans/2026-08-11-photo-palette-overflow.md`
- **Byte-identity goldens are scoped to one stage, not the whole pipeline.** A frozen whole-pipeline snapshot goes stale the first time anything downstream legitimately changes and then tests "nothing anywhere ever changes". Re-capture only for a change that knowingly moves that stage, and say so in the commit. `plans/2026-08-10-sam2-segmentation.md § Task 1`
- **Additive-lane discipline:** each new lane must leave the previously shipped lanes byte-identical, and the invariant must live structurally as a single `if` at the dispatch point rather than as a promise. `plans/2026-08-02-photo-digitizing-steps1-2.md § Scope`, `plans/2026-08-02-photo-digitizing-step4-region-former.md § Scope`
- **Export: dst/exp/pes prefer the service's pyembroidery encoder,** the trustworthy path for third-party software (the browser DST encoder is confirmed transposed a quarter-turn against Tajima); any service failure falls back to the browser encoder with no visible error, and `svg` never touches the service. `plans/2026-08-10-fix-export-routing.md`
- **Stage 0 classification is a thresholded decision tree over three cheap signals, not ML;** ties/low confidence fall to `flat` (the proven default) with `CLASSIFICATION_UNCERTAIN` rather than silently guessing photo. `cfg.forced_class` is the escape hatch for tests and the eventual UI override. `plans/2026-08-02-photo-digitizing-steps1-2.md § stage0_classify contract`
- **The gradient blend tier parameterizes the existing tatami emitter** — one shared fill angle, per-layer spacing `0.4mm x N`, phase-offset layers summing to 1.0-1.2 coverage, reusing the existing ΔE00 chart code. That reuse is the whole reason the step was cheap. Non-ramp (speckly) residuals fall back to ordinary tatami. `plans/2026-08-02-photo-digitizing-steps1-2.md § stage6_blend contract`
- **Enclosed-background regions become real regions and are excluded at stitch time, not at mask time.** They stay in `PipelineResult.regions` (the review payload must list them so Studio can offer a restore control); the filter happens at `plan_stitches`. `enclosed_background` is a fact recomputed every generation (like `layer`, unlike `border`/`tier` — no carry-forward), and ambiguous tagging fails open. One new override key `stitched` is added rather than an inverse-deleted list, because that is the smallest addition consistent with the existing contract. `plans/2026-08-04-enclosed-background-restore-design.md`
- **DT-first premise:** commercial auto-digitizers compute contour, skeleton and distance transform as one artifact and decide satin-vs-fill from DT statistics at skeletal pixels; EMB-Bot decides from `2*area/perimeter` before any DT exists. Measured consequence: the same design in two file encodings (`logo_alpha` vs `logo_whitebg`) sews the same shape as satin in one and fill in the other, purely on antialiasing noise (4.997 vs 5.033 against a 5.0mm cap). Every DT arm calls it fill on both. `plans/2026-08-03-dt-first-sequencing.md`, `plans/2026-08-04-m0-shape-lens-measurement.md`
- **Cost shape of DT-first:** a full restructure (DT for every region) is ~10-23% of stages 1-4; "add-a-term" arms that only refine what the shipped rule already called satin cost ~1.5-1.8%, because stage 6 already pays for a medial axis on that subset — work moved earlier, not new work. Variance alone is insufficient (a 14x wedge taper still reads "uniform"), so any arm must pair variance with a width term. `plans/2026-08-04-m0-shape-lens-measurement.md`
- **SVG import (decisions recorded even though the branch died):** pure JS, no DOM, so engine modules run under `node --test` — the browser's `getPointAtLength` was rejected because jsdom stubs it; flattening tolerance resolves in **final mm** via `targetLongMm`, not source units (a source-pinned tolerance silently coarsens as a design scales — the same bug class as the 2026-07-27 density regression); no flatten/median-cut over SVG colors, since an SVG states its palette exactly; identical fills across elements merge into one region to cut thread changes. `specs/2026-07-27-svg-import-and-shapes-design.md §§ 3.2-3.4`
- **Shape labels are human-authored at import; glyph letters are never surfaced** ("a star must never be press k"), and an unlabelled glyph is excluded rather than shipped. Pack LICENSE text is carried into the pack record. `plans/2026-07-27-svg-import-and-shapes.md § Task 10`

## Rejected alternatives

- **Torch (or any deep-learning stack) in the shared `digitizer/.venv`** — would put the exact numpy/OpenCV pins that feed golden tests at the mercy of torch's transitive resolution. `plans/2026-08-10-sam2-segmentation.md § Task 2`
- **`pip install sam2` from PyPI** — an unrelated third-party project. Meta's distribution is `SAM-2`, GitHub-only, import package `sam2`; a test guards `CHECKPOINT_BASE_URL` against mirrors. Same doc, Global Constraints.
- **SAM2 for the `gradient` class** — no distinct objects to find, and SLIC+RAG is already tuned against two real gradient fixtures. `plans/2026-08-10-sam2-segmentation.md § Task 3`
- **Ranking overlapping SAM2 masks by `predicted_iou`** — one large confident mask would erase every small feature inside it, the exact opposite failure. § Task 2.
- **Global k-means for photo/gradient input** — clusters color independent of position, so a smooth ramp dithers into ordered bands: 192-208 final regions on `drone_render.png` versus 45-56 for SLIC+RAG with a retuned merge threshold. `plans/2026-08-10-sam2-segmentation.md § Task 5`, `plans/2026-08-02-photo-digitizing-step4-region-former.md`
- **Per-region nearest-thread snap before dedupe** — replaced by joint palette selection so near-duplicate spools consolidate. `plans/2026-08-10-sam2-segmentation.md § Task 1`
- **Reporting `len(thread_indices)` as the region count** — was a real defect (color count wearing a region-count label); fixed 2026-08-04. Same section.
- **A whole-pipeline frozen snapshot** as the refactor-safety net — rejected for staleness; per-stage goldens instead. § Task 1.
- **Threading venv path overrides through `PipelineConfig`** — rejected; module constants. § Task 3.
- **A client-side trick riding `deleted_shape_ids`** to restore enclosed regions — impossible, because the client can never have cached an id that was never in any prior response. `plans/2026-08-04-enclosed-background-restore-design.md`
- **Ink/Stitch pictogram packs as satin fonts** — verified false on 2026-07-27 (0 satin columns in the fill-based packs, sanity-checked against two known-good imports at 318/548). The flowers Kent asked for exist only in fill-based packs, so there is no satin route to shapes. `specs/2026-07-27-svg-import-and-shapes-design.md § 2`
- **Browser DOM curve flattening (`getPointAtLength`)** — correct and free, but jsdom stubs it, which would put the module outside the Node suite. § 3.2. **Arc→bézier→polyline** was also rejected: everything flattens to polylines anyway, so sample the arc's parametric form directly. `plans/2026-07-27-svg-import-and-shapes.md § Task 3`
- **"VP90 is vindicated"** — explicitly refused as a conclusion. The earlier "do not land" audit verdict was correct at `SATIN_MAX_WIDTH_MM = 3.0`; the cap later moved to 5.0 for unrelated corpus reasons, which flips the synthetic result to 0/21 wrong. A 21-shape set is known too small to settle it — the verdict needs re-measuring against the corpus at today's cap, not reversing. `plans/2026-08-04-m0-shape-lens-measurement.md`

## Sequence claims

- **SAM2: the shared-tail extraction and its golden must land and commit BEFORE any SAM2 code exists.** The golden is captured against unmodified `segment()` and must be GREEN before *and* after the refactor (red-green is deliberately inverted — a red here means the golden was captured wrong). Then config/warnings/availability → seam → pipeline dispatch → live acceptance. `plans/2026-08-10-sam2-segmentation.md § Tasks 1-6`
- **Before building the isolated venv:** re-read Meta's current README (repo name, checkpoint URLs, hydra config paths are the things most likely to have moved) and confirm ≥4 GB free disk — a pip install that runs out of disk leaves a broken venv the availability check happily calls "present". § Global Constraints, § Task 6 Step 1.
- **Export routing:** service client → orchestration function → the single `DownloadStep.svelte` call site (grep-confirmed as `exportDesign`'s only production caller). `plans/2026-08-10-fix-export-routing.md`
- **Photo plan ordering as actually executed:** steps 1-2 (classifier + gradient blend) → step 4 (SLIC+RAG region former, deliberately taken *before* step 3 because step 3's only hard dependency was the face-local threshold drop and `stage1_prep` already did background detection) → step 3 → steps 5+. `plans/2026-08-02-photo-digitizing-step4-region-former.md § Why this one, and why not step 3 first`
- **Queue pinned 2026-08-03:** (1) gradient-fragmentation + enclosed-white regressions and the bg-existence guard, (2) DT-first M0+M1, (3) photo steps 5+, (4) M2/M3 onward once the corpus disagreement table exists. Photo steps 5+ were moved behind M0/M1 because they are new stitch-tier decisions built on the satin-vs-fill classifier the migration replaces. `plans/2026-08-03-dt-first-sequencing.md`
- **M1 requires byte-identical output, proven by the M0 instrument before flipping anything,** and ships behind `cfg.extra["shapefield"]` defaulting to today's path. Same doc.
- **Palette overflow:** verify against the real `drone_render.png` fixture and read all 14 fixtures x 2 configs before re-capturing the scorecard baseline — capturing early would adopt a regression as the new normal. `plans/2026-08-11-photo-palette-overflow.md § Task 3`
- **Shapes cannot ship before the SVG parser exists** (§2 of the spec inverts the originally-planned order). Within the SVG plan, Task 6 was a hard risk gate: render two real packs and STOP for a human decision before Tasks 8-10 build a picker on the assumption. `svgpath.js` must load before `svgimport.js`, and `ENGINE_FILES` is mirrored in three places that must move together. `plans/2026-07-27-svg-import-and-shapes.md §§ Global Constraints, Task 6, Task 7`
