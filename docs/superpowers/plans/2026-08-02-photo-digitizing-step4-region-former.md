# Photo Digitizing — Step 4: SLIC + RAG Region Former

Status: DRAFT for adversarial critique. Implements step 4 (of 10) from
`docs/photo-digitizing-plan-2026-07-31.md` — the actual "handle complex
images" capability. Steps 1–2 (classifier + gradient blend tier) already
shipped tonight; this is the next slice, not a continuation of that one.

## Why this one, and why not step 3 first

The source plan sequences step 3 (background removal via rembg, face
detection via YuNet, texture-kill preprocessing) before step 4. Building
step 4 without step 3 anyway is a deliberate scope cut, not an oversight:

- Step 3's rembg dependency is real added surface — a new package, a model
  cache policy, download-on-first-use behavior. Worth its own session.
- Step 4's only *hard* dependency on step 3 is the "face-local threshold
  drop" refinement (lower the merge threshold near a detected face so eyes/
  mouth survive as their own regions) — everything else in step 4 (SLIC
  oversegmentation, RAG perceptual merging, min-area floor, thread
  snapping) stands on its own.
- `stage1_prep.prep()` already does background detection (alpha-aware or
  border-flood) independent of any classification — reusable as-is here,
  no rembg needed for this slice.

**Deferred, explicitly, not silently:** face-local threshold dropping
(needs step 3's face priors), true photo-subject portrait/pet quality (that
needs steps 5–8 too — direction fields, streamline tier). What ships here
is the actual segmentation upgrade: replacing global k-means (which
"dithers gradients into speckle" because it clusters color independent of
spatial adjacency) with SLIC + perceptual region-merging for
photo-classified input, producing 20–80 sewable regions with photographic
boundaries instead of thousands of one-pixel speckles.

## Scope

- `stage2_photo_segment.py` — new module, drop-in alternative to
  `stage2_quantize.quantize()` for photo-classified designs. Same output
  contract (`Quant`-compatible: labels HxW int, palette, warnings) so
  everything downstream (stage3 small-region absorb, stage4 vectorize) runs
  completely unchanged — this stage owns segmentation quality, nothing else
  in the pipeline needs to know SLIC exists.
- `pipeline.py` — one dispatch point: when `classification.class_` is
  `photo_subject` or `photo_scene`, call `stage2_photo_segment.segment()`
  instead of `stage2_quantize.quantize()`. `flat` and `gradient` classes
  are untouched — this is purely additive, same discipline as steps 1–2.
- **Hard invariant, same as last time**: flat and gradient lanes stay
  byte-identical. This only activates on classes that currently have zero
  dedicated handling (they fall through to the ordinary flat pipeline today
  with just a warning attached) — so there's no existing "photo lane
  output" to preserve; the invariant is about *not touching* the other two
  lanes, not about matching a prior photo-lane baseline.

## Deviations from the source plan (flag if wrong)

1. **No rembg, no face priors** — see above. `_face_local_threshold` is a
   documented no-op hook (accepts a `face_regions` param, always `None` for
   now) so step 3 wiring it in later is additive, not a rewrite.
2. **`skimage.future.graph` doesn't exist in this venv's skimage (0.26.0)**
   — the source plan's exact import path is stale. `RAG` /
   `merge_hierarchical` / `rag_mean_color` live at `skimage.graph` now.
   Same functions, moved module.
3. **New fixture needed.** The existing `testdata/photo/photo_subject_stub.png`
   / `photo_scene_stub.png` are pure noise / gradient+texture — built to
   trip the *classifier's* signals, not to have real photographic
   structure worth segmenting. `drone_render.png` classifies as `gradient`,
   not photo, so it won't even route here. Adding
   `tools/make_photo_region_fixture.py`: deterministic soft-edged color
   blobs (a few overlapping Gaussian-falloff regions) — the direct test of
   the core claim, since a naive per-pixel k-means dithers a soft edge into
   speckle while SLIC+RAG should hold it as one or two clean regions.

## `stage2_photo_segment.py` contract

`segment(prep: Prep, cfg: PipelineConfig, face_regions=None) -> Quant`
(same return type `stage2_quantize.quantize()` produces — reuse the
dataclass, don't redefine it).

1. **SLIC oversegmentation**: `skimage.segmentation.slic` on the Lab-space
   image, foreground pixels only (`prep.bg_mask` excluded, matching how
   stage2_quantize already excludes background from clustering).
   `n_segments` targeting ~800–2000 per the source plan, `compactness`
   tuned for irregular (not grid-like) boundaries, seeded (`start_label=1`,
   no randomness — SLIC's own algorithm is deterministic given fixed
   inputs, confirm this in the determinism test rather than assume it).
2. **RAG construction**: `skimage.graph.rag_mean_color` over the SLIC
   labels, mean color in Lab.
3. **Hierarchical merge**: `skimage.graph.merge_hierarchical` with a
   ΔE00 (CIEDE2000, reuse `threads.rgb_to_lab`/existing ΔE machinery —
   no new color-distance implementation) edge-weight threshold. Threshold
   is a tuned constant, measured against the new fixture and named (not a
   magic number), analogous to how `RAMP_R2_MIN`/`RAMP_SPECKLE_MAX` were
   tuned for the blend tier.
4. **Min-area floor**: regions under ~2–3mm² at hoop scale (convert via
   `prep.px_per_mm`, matching `cfg.min_detail_mm`-style floors elsewhere)
   force-merge into the neighbor they share the longest boundary with —
   same rule `stage3_segment.resolve_small_regions` already uses for
   classical segmentation, reused not reinvented.
5. **Face-local threshold drop**: `_face_local_threshold(face_regions)`
   documented no-op for this slice (see Deviations).
6. **Thread snapping**: each final region's mean Lab color → nearest
   thread via the existing chart lookup (`threads.py`), same call
   `stage2_quantize` already makes — reuse, don't reimplement.
7. **Output**: `Quant(labels=<HxW int, background=-1>, thread_indices=[...],
   warnings=[...])`. New warning code `PHOTO_SEGMENT_REGION_COUNT` (info,
   not a problem) carrying the final region count, useful for the acceptance
   check and for whoever tunes this against real photos later.

## Tests

1. **Region-forming beats naive per-pixel clustering on a soft edge**
   (`region_blobs.png`, the new fixture): assert final region count is in a
   tight, small range (bounded above — e.g. under 15 for a 3-blob fixture —
   proving merge actually consolidated, not just relabeled SLIC's raw
   output); assert no region's boundary reads as salt-and-pepper noise
   (a cheap proxy: each region's pixel mask, eroded by 1px, still covers
   most of its own area — speckle collapses under erosion, a clean region
   doesn't).
2. **Min-area floor**: a deliberately tiny constructed sliver gets absorbed,
   not left as its own region — mirrors `test_stages.py`'s existing
   absorbed/dropped small-shape tests for the classical path.
3. **Determinism**: same input segmented twice → identical labels, identical
   region count. Pin as a canary per this codebase's established pattern.
4. **Full-pipeline integration**: `run_stages()` on `region_blobs.png` with
   `cfg.forced_class="photo_scene"` produces valid `Region` objects that
   flow all the way through stage4 vectorize without error — the
   drop-in-replacement contract actually holds, not just the function
   signature.
5. **Flat/gradient lanes untouched**: re-run the existing
   `test_flat_lane_byte_identical.py` fixtures (they should need zero
   changes — this is the same invariant, exercised as a side effect of
   adding a third routing branch).

## Non-goals for this plan (resist creep)

Background removal / rembg (step 3), face detection (step 3, though the
hook is left open), texture-kill preprocessing (step 3), direction fields
(step 5), mono tonal tiers (step 6), palette k-medoids for photo classes
(step 7), the streamline/portrait tier (step 8, patent-adjacent), guardrail
preflight scoring for this new stage (step 9), the sew-out gate (step 10).
Real-photo quality validation (does this actually look good on Kent's own
portrait/pet/scenery photos) explicitly waits for steps 5–8 to exist —
this slice's job is proving the segmentation mechanism works, not
shipping customer-facing photo quality.
